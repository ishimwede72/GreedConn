# Security

This document describes Greedcon's threat model and the controls that implement it. Every statement here maps to code in `src/security/`, `src/messaging/`, `src/engine/`, `src/testing/` and `src/authentication/`.

## 1. Threat model

**What we protect**

| Asset                                                                                                | Where it lives                                           |
| ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Credentials (bearer tokens, basic passwords, API keys, OAuth2 client secrets, access/refresh tokens) | VS Code `SecretStorage` (OS keychain/credential store)   |
| Your collections, environments, history, settings, test runs                                         | JSON files under VS Code `globalStorage`                 |
| The integrity of your machine and network                                                            | — (the extension runs with your full VS Code privileges) |

**Who we defend against**

1. **Anything executing inside the webview** — a compromised script, an injected payload, or a crafted message. The webview is treated as an _untrusted_ boundary even though Greedcon ships its own UI.
2. **Hostile server responses and redirect chains** — HTML/JS bodies, header injection attempts, oversized bodies, redirect loops pointing at internal hosts.
3. **Hostile import files** — Postman/Greedcon collection JSON crafted to blow up memory, smuggle headers, or smuggle script content into tests.
4. **Accidental self-harm** — secrets pasted into fields and then written into collections/history/exports/logs.

**What is out of scope:** a malicious VS Code build, a compromised extension host process, or an attacker with filesystem access to your `globalStorage` directory (they could read your non-secret data directly; secrets still require the OS credential store).

## 2. Webview as an untrusted boundary

**Content Security Policy.** Every webview HTML is generated by `src/security/WebviewSecurity.ts`:

```
default-src 'none';
img-src <cspSource> data:;
style-src <cspSource> 'unsafe-inline';
script-src 'nonce-<nonce>';
font-src <cspSource>;
connect-src <cspSource>;
frame-src 'self' data:;
form-action 'none';
base-uri 'none';
object-src 'none'
```

- A fresh **32-character nonce** is generated per load (`generateNonce()`), and only `<script nonce=… src=media/webview.js>` carries it — no inline script, no `eval`, no remote resources of any kind (`default-src 'none'`).
- Resources are loaded only from the webview's own `cspSource`; `webview.options.localResourceRoots` is restricted to the extension directory.
- `form-action 'none'` and `base-uri 'none'` block form hijacking and `<base>` rewriting.

**Rendering.** The webview never assigns untrusted text to `innerHTML`: `webview/components/dom.ts` documents and enforces `textContent`-only content, and `JsonViewer` builds response highlighting from text nodes. Response bodies, header values, URLs, collection names and toast messages therefore render inert.

**Message validation.** Inbound messages are validated field-by-field by `src/messaging/MessageValidator.ts` before any handler runs (see [ARCHITECTURE §2](./ARCHITECTURE.md#2-message-protocol-src-typesmessagesmsgsrcmessaging)). Unknown message types are rejected outright; string lengths, array counts (≤ 500 params/headers, ≤ 200 tests) and body sizes are capped, and control characters are stripped with `sanitizeText`/`sanitizeMultiline`. `src/security/InputSanitizer.ts` additionally strips control characters, escapes HTML where strings are interpolated, sanitizes file names and guards against prototype-polluting keys (`safeKey`).

**No remote content.** The UI has no `fetch`/XHR calls; the only outbound network code in the whole extension is `HttpClient` (user-initiated requests) and the OAuth2 token/loopback code.

## 3. Secrets

- **Storage.** Credentials entered in the Auth tab and secret environment variables are written to VS Code `SecretStorage` through `src/security/SecretManager.ts` (`greedcon.secret.<id>` keys plus a metadata record). Collections, environments, history, settings and test-run files store an opaque `secretId` — never the configured credential value. Other request content is stored as authored; use the Auth tab or a secret environment variable for credentials instead of embedding them in URLs, query rows, headers, or bodies.
- **On save.** `AuthenticationManager.prepareForStorage()` moves the plaintext field into SecretStorage and replaces it with the mask `••••••••` before the config is persisted.
- **To the UI.** `maskForDisplay()` and `EnvironmentManager.listMasked()`/`getMasked()` send masked values to the webview; secret environment variables render as `••••••••` (`webview/pages/EnvironmentsPage.ts` uses the same `••••••••` constant). Response cookies are masked, and known request credentials are scrubbed from reflected response text and headers.
- **At execution.** `prepareForExecution()` re-materializes real values into a throwaway object used only for the duration of the send; the result is never persisted or posted back to the webview.
- **In logs and URLs.** `src/utils/Logger.ts` masks sensitive headers and `Bearer <token>` values. Secret-looking query parameter names (such as `token`, `api_key`, `signature`, and `password`) are masked in logs, history URLs, exports, and response content; configured custom API-key query names are masked too. Reflected custom query credentials are removed from stored/displayed response bodies and headers.
- **In exports.** Environment exports are produced from the _masked_ view (`environments.export` handler). Collection export passes the collection through `RedactionManager.redactObject()`, which masks sensitive-looking keys (`token`, `secret`, `password`, `api key`, `authorization`, `credential`, `refresh`); saved auth configs additionally hold only the `••••••••` mask plus an opaque `secretId`, never the plaintext value.
- **Deletion.** `SecretManager.delete()` removes the value from SecretStorage immediately and drops its metadata.

## 4. Declarative tests — no script execution

Greedcon deliberately has **no user-supplied script runner** (no `eval`, no `vm`, no `Function`):

- Tests are data: `TestDefinition { assertions[], extractions[] }` validated by `TestParser`.
- Evaluation happens in the extension host in `src/testing/` via a fixed dispatch (`status`, `responseTime`, `body`, `header`, `jsonPath`) with a bounded operator set (`equals`, `contains`, `matches`, `exists`, `lt`, …) and JSON-path lookups.
- Regex assertions go through `safeRegex()` (`src/testing/assertions/shared.ts`): patterns longer than 1000 characters are rejected, flags are restricted to `i`/`m`/`s`, and an invalid pattern yields an `error` result instead of throwing. Assertion evaluation is wrapped in try/catch.
- Extractions only write a _string value_ into the active environment (`EnvironmentManager.setExtractedValue`), which is data, not code.

An imported collection that claims to contain "scripts" cannot introduce any: unknown fields are dropped by `TestParser`, and `MessageValidator` rejects malformed test payloads.

## 5. URL policy (`src/security/UrlValidator.ts`)

| Rule                               | Behavior                                                                                                                                        | Default                                                                                                               |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Protocol allow-list                | only `http:` and `https:`; anything else (`file:`, `ftp:`, `data:` …) rejected                                                                  | fixed                                                                                                                 |
| No credentials in URL              | `user:pass@host` rejected — “use the Authorization tab instead”                                                                                 | fixed                                                                                                                 |
| URL length                         | ≤ 8192 characters                                                                                                                               | fixed                                                                                                                 |
| Private/loopback targets           | loopback (`127.0.0.0/8`, `::1`, `localhost`), RFC1918, link-local, `.local`/`.internal`/`.localhost`, IPv6 ULA/link-local classified as private | **allowed** (local API testing is the primary use case) — disable with `greedcon.security.allowPrivateNetwork: false` |
| HTTPS → HTTP downgrade on redirect | blocked per hop by `validateRedirect()`                                                                                                         | blocked (`greedcon.security.allowHttpsToHttpRedirect: false`)                                                         |
| Bare hosts                         | `api.example.com/path` is assumed `https://`                                                                                                    | fixed                                                                                                                 |
| `{{variables}}`                    | shape-checked pre-flight with placeholders substituted; full validation runs after variable resolution                                          | —                                                                                                                     |

Private/loopback detection is hostname-based (`isPrivateHostname`); it is a guard rail against accidental SSRF-style redirects, not a substitute for your own network policy.

## 6. Redirect handling (`src/engine/HttpClient.ts`)

- Redirects `301/302/303/307/308` are followed only while `followRedirects` is on and `redirectCount < maxRedirects` (0–20, default 5).
- **Every hop is re-validated** against the URL policy; a rejected hop stops the chain and returns the last response (logged as `redirect blocked`).
- **`authorization` and `cookie` headers are deleted when the origin changes** (protocol, host or port differ), so credentials never leak across origins.
- 303 always becomes GET; 301/302 downgrade POST to GET and drop `content-type`/`content-length` (browser parity).
- `Host` is never user-settable (derived from the URL by the client).

## 7. Header sanitization (`src/security/HeaderSanitizer.ts`)

Every header passes through before it reaches the socket:

- **CR/LF/NUL injection**: rejected in both name and value (`Header … contains illegal control characters`).
- **Name grammar**: must match the RFC token set `[!#$%&'*+\-.^_`|~0-9A-Za-z]`, max 256 chars; values max 16 384 chars.
- **Forbidden hop-by-hop / client-managed headers**: `host`, `content-length`, `transfer-encoding`, `connection`, `upgrade`, `te`, `trailer`, `proxy-authorization`, `proxy-connection`, `keep-alive` cannot be set manually (they are managed by the HTTP client).
- Rejections are surfaced as warnings instead of silently disappearing.

## 8. Input sanitization and size caps

| Cap                          | Value                                                                | Where                                                                                             |
| ---------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Message id                   | ≤ 128 chars                                                          | `MessageValidator`                                                                                |
| Request URL (inbound)        | ≤ 8192 chars                                                         | `MessageValidator` / `UrlValidator`                                                               |
| Params / headers per request | ≤ 500 rows (inbound), ≤ 200 params + ≤ 100 headers enforced at build | `MessageValidator`, `RequestValidator`, `SecurityManager.DEFAULT_LIMITS`                          |
| Request body                 | ≤ 20 MB                                                              | `RequestValidator` (`maxRequestBodyBytes`)                                                        |
| Response body retained       | ≤ 10 MB default (configurable 1 KB–512 MB)                           | `greedcon.request.maxResponseBytes`, streamed cap in `HttpClient` (socket destroyed past the cap) |
| Import content               | ≤ 10 MB (collections), ≤ 5 MB (environments)                         | `MessageValidator`                                                                                |
| JSON format/validate text    | ≤ 5 MB                                                               | `MessageValidator`                                                                                |
| History body                 | ≤ 64 KB per entry (only if `greedcon.history.storeResponseBody`)     | `HistoryManager`                                                                                  |
| Control characters           | stripped from all boundary-crossing strings                          | `InputSanitizer`                                                                                  |
| File names                   | dangerous characters stripped                                        | `InputSanitizer.sanitizeFileName`                                                                 |

`JsonStorage.resolve()` accepts only the five known `.json` file names, preventing path traversal out of the data directory.

## 9. Redaction (`src/security/RedactionManager.ts` + `HeaderSanitizer`)

- **Sensitive headers** (`authorization`, `proxy-authorization`, `cookie`, `set-cookie`, `x-api-key`, `x-auth-token`, `x-access-token`, `api-key`, `apikey`) are stored in history as `••••••••` — the header's _presence_ is preserved so "header exists" assertions can still be reviewed, the value is not (`redactHeadersForStorage`). Other header values and exported strings also have secret-looking URL query parameters masked.
- **Sensitive-looking keys** (`token|secret|password|api key|authorization|credential|refresh`) are masked in objects before display/export (`redactByKey`, `redactObject`).
- **Known secret values** can be scrubbed from free text (`redactKnownSecrets`, values ≥ 4 chars).
- **Logs** always pass through `redactString` (Bearer-pattern masking) regardless of log level.

## 10. Configurable security settings

All policy comes from VS Code configuration (`src/configuration.ts`, read through `SecurityManager`), so it can be set per user or per workspace:

| Setting                                      | Default                                      | Effect                                                                      |
| -------------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| `greedcon.security.allowPrivateNetwork`      | `true`                                       | `false` blocks requests to loopback/private addresses                       |
| `greedcon.security.allowHttpsToHttpRedirect` | `false`                                      | `true` permits HTTPS→HTTP protocol downgrade on redirects                   |
| `greedcon.request.validateSsl`               | `true`                                       | TLS certificate validation (disable only for local self-signed dev servers) |
| `greedcon.request.timeout`                   | `30000` ms (100–600000)                      | Default request timeout                                                     |
| `greedcon.request.maxRedirects`              | `5` (0–20)                                   | Redirect budget                                                             |
| `greedcon.request.maxResponseBytes`          | `10485760` (10 MB)                           | Response body retention cap                                                 |
| `greedcon.history.enabled`                   | `true`                                       | Master switch for recording history                                         |
| `greedcon.history.limit`                     | `200` (10–5000)                              | Maximum history entries kept                                                |
| `greedcon.history.storeResponseBody`         | `true`                                       | Store (capped) response bodies in history                                   |
| `greedcon.storage.autoBackup`                | `true`                                       | Declared for rotating backups of the data files (see note)                  |
| `greedcon.logging.level`                     | `info` (`error`/`warn`/`info`/`debug`/`off`) | Output-channel verbosity — credentials are redacted at every level          |

The Settings page surfaces a **Security** card summarizing these protections and links to VS Code settings (`app.openSettings`).

> Note on backups: `JsonStorage` always keeps three rotating `.bak` files per data file regardless of configuration; `BackupManager` snapshots are created on demand.

## 11. OAuth 2.0 specifics (`src/authentication/OAuth2Auth.ts`)

- **Client Credentials** — token request to the configured `tokenUrl`, which must parse as a URL with `http:`/`https:` (`requestToken` rejects any other protocol); the client secret is read from SecretStorage for the request only.
- **Authorization Code + PKCE** — a one-shot loopback listener on `http://127.0.0.1:<53000–53999>/callback`, random `state` (24 chars) and `code_verifier` (64 chars), S256 challenge, 3-minute authorization timeout, server closes after the first callback. Tokens are stored only in SecretStorage; no token value is logged.

## 12. Data at rest

- **Local only.** Collections, environments, history, settings and test runs are plain JSON files in VS Code's `globalStorage` (`…/User/globalStorage/greedcon.greedcon/`). There is no cloud component, no sync, no account.
- **No telemetry.** The extension contains no analytics/telemetry code or dependencies; the only network traffic is the HTTP requests you send and OAuth2 flows you start.
- **Recovery, not exfiltration.** Corruption quarantine files (`*.corrupt.<ts>`) and backups (`.bak.N`, `backups/<stamp>_<label>/`) stay in the same local directory.
- **Uninstall** removes the extension code; your data directory and SecretStorage entries remain until you delete them (see [INSTALLATION.md](./INSTALLATION.md#uninstall--cleanup)).

## 13. Reporting

If you find a security issue in Greedcon, please report it privately to the maintainers via the repository listed in `package.json` rather than opening a public issue.
